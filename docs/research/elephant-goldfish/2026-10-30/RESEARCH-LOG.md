## Initial upstream observations to retain and verify in synthesis

These are source observations, not efficacy results. Paths below belong to the pinned Google repository.

- `README.md`: fresh means no earlier conversation, not no source access. Reviewers read the draft and referenced source. Small clear bug fixes should use ordinary workflow. Claims thousands of Google engineers use EGM; adoption does not establish comparative defect reduction.
- `plugin.json`: version 0.1.0, local-executor requirement in OpenAI interface metadata, host models/permissions, partial cloud support. These declarations do not themselves establish enforcement.
- `resources/execution_instructions.md`: design-only, scratch code outside source tree, explicit consensus, one question per response, no summaries, contradiction stops all writes in discovery turn. These are instructions, not an executable controller.
- `skills/egm-review/SKILL.md`: five stages numbered 5–9: initial zoom-out, comprehension, critic, intermediate zoom-out, readiness. Four presets differ materially. Uninterrupted mode directly dispatches the five review stages and consolidates findings; interactive critic/readiness subflows invoke the iterative review loop. Do not imply every preset executes identical repair/convergence mechanics.
- Review semantic split: high-level feature range versus detailed implementation range; detects standard headers, asks on ambiguity, permits feature-only review. Re-read line bounds after edits. Full document/source access differs from the active scope.
- Comprehension bypasses synthesizer, preserves complete two-part paraphrase even with no findings. It does not apply the re-implementation standard. This protects the signal from findings-only lossy aggregation.
- Intermediate zoom-out explicitly receives initial zoom-out report and focuses on additions/mitigations. This is deliberately not total blindness to all earlier review artifacts.
- Interactive stage manual edits/re-audits have a one-re-audit cap with auto-advance and residual accepted-trade-off language. This differs from the review-loop five-round cap and user choice. Potential authority/acceptance nuance to scrutinize, not silently normalize.
- `skills/egm-review-loop/SKILL.md`: per-round semantic target re-resolution; fresh parallel reviewers; optional synthesizer; stable finding IDs; failed reviewer retries once then marked not run. Missing status is not a clean reviewer.
- Review-loop convergence: two consecutive clean rounds, maximum five by default; clean is decided before applying current-round fixes; no unsettled Blocker/Major, nits do not block, missing reviewer prevents clean. Contested/accepted-risk findings settle; applied fixes do not settle. Same-scope recurrence reopens a failed/regressed fix. Churn means a new finding at a fixed scope that reverting the fix would resolve. At cap/churn ask accept/continue/redraft. Explicit user turn checkpoint remains between iterations.
- `skills/egm-resolve/SKILL.md`: four actual categories CONTEST, ESCALATE, PROPOSE FIX, DECLINE, despite older descriptions mentioning only two. Contest requires evidence available to reviewer; hidden institutional evidence escalates; comprehension gaps cannot be contested; do not change severity; do not add context solely for a zero-context reviewer if a human reader does not need it. Author ownership is explicitly checked by acknowledging author's wish to contest is not evidence.
- Resolver marks report `Status: resolved` even though handoff counts can include escalations and remaining unaddressed issues. Therefore resolved is workflow completion, not all defects fixed.
- `skills/egm-brainstorm/SKILL.md`: multi-turn clarification then explicit readiness, six concurrent lenses: YAGNI, cost/quota, UX, migration, observability, maintenance. Final concepts brief records alternatives so drafting need not invent forgotten reasons. Publishing option means writing a design/RFC file and optional sitemap, not inherently a remote publication tool.
- `skills/egm-draft/SKILL.md`: predecessor priority explicit file → concepts brief → discussion summary → interactive intake. Section-by-section approval. Human must choose defensible architecture even if they request the agent choose. This is a deliberate usability/authority trade-off, not a universal virtue to import.
- Draft finalization compares against predecessor: contradictions plus architectural/interface/dependency additions; quotes both; user resolves; draft may be right after inspecting code. Fresh reviewers cannot reconstruct omitted predecessor decisions if brief is excluded. Actual review reads referenced material, so the statement “no Goldfish reads the brief” is a workflow convention, not a capability prohibition.
- `agents/comprehension.md`: understands software but not this project; avoids flagging general engineering terms. Paraphrases proposal and existing-system description in 2–5 sentences each; inability to paraphrase is Blocker. A wrong paraphrase is a finding for author comparison.
- `agents/synthesizer.md`: normalization/deduplication, optional A/B independent instances of each persona, reviewer status, artifact output. Optional doubled instances are not a guaranteed recall improvement; source phrase “eliminate non-deterministic evaluation gaps” overstates what sampling can prove.
- `docs/designs/architecture.md`: stale narrative says four tiers and labels readiness Step 8, unlike current skill's five stages with intermediate zoom-out at 8/readiness at 9. Its persona summary also omits some current roles. Final report must privilege actual skill instructions and explicitly flag doc drift. Architecture's claims about monolithic review and comments/kLOC are design rationale, not presented benchmark data.
