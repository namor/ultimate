# Weekly reimagining

Find one improvement worth testing. Report it without changing the project. Dream handles memory and chapter maintenance; this review looks for improvements to the product and how work gets done.

1. Read the current project instructions and inspect recent work. Start with the last completed reimagining if one exists. Look for repeated waits, corrections, expensive reads, dropped handoffs, or a capability people could use with less effort. Check the source or loaded behavior before proposing something the project may already do.
2. Compare up to three distinct opportunities. Use bounded reads and cite the evidence by conversation entry, file, or version. Inspect active work so you do not recommend a duplicate. Keep raw logs and private artifacts local. Quote only what the recommendation needs; never include secrets or sensitive payloads.
3. For each opportunity, state what the user does today and what would change. Name the smallest experiment that could disprove the idea, what to measure, the threshold for continuing, and the tradeoff. Include a stop condition for any authority, privacy, or reliability risk. If the evidence supports fewer ideas, report fewer.
4. Recommend one experiment and explain why it comes first. If none merits a test, say what evidence is missing. Link the full report if you send a short summary.

This is a read-only review. Do not run the proposed experiments, edit memory or settings, start implementation or background jobs, change permissions, or publish anything. The user decides what to try. Preserve existing trust, privacy, review, and delivery gates.
