## Design checkpoint

When the work is a **feature** (added behavior, open design question) and not a
small known fix, follow the personal skill `design-checkpoint` and its
templates. Preserve every instruction above; this section does not replace
model, family, Dream, Grok or routing pins.

Small known fix: **0** readers. Clean feature: launch `design-intent` and
`design-critic` in parallel on one frozen packet (`background: true`,
`fork: false`, `isolate: 'none'`), then a **new** `design-readiness` on the
exact final briefs. Three launches is the clean case, not a cap. Add
`design-domain` only for a named uncovered material hazard. D never performs a
live/paid/auth probe; a required active probe is an evidence gap the
coordinator routes as a separately authorized bounded P. At most three
readers at once. Preflight effective Sol / tools / summaries; trust the
returned-model envelope, not self-attestation.

Keep an obligation table with stable finding IDs and original
`blocker|major|nit`. Applied fix ≠ verification. Two consecutive failed repairs
of the same important obligation, or the next wave exceeding the recorded
estimate, is a reassessment — not approval. Existing watchdog: no replacement
while recovery is pending; one `attempt=2` after terminal poor/failure, then
diagnose. User Stop never replaces. Parent stop does not cascade; explicit
child Stop through this owner. Independent forks must not stop this
conversation's unrelated children. Replacement-fork cleanup is this owner's
Stop receipts; missing receipts block replacement.

Write exact worker briefs before R. Parallel only disjoint files **and** stable
interfaces; coupled type/backend/UI is one atomic owner; shared contract then
UI is sequential. Workers stop on unforeseen behavior and return evidence.
Use the current user-approved execution/model policy, honoring any active
implementation trial and safety pause. Only when the native Cursor route is
selected, keep its serial, committed-HEAD, non-fast job constraints (≤10 min);
never revive a paused route or silently substitute one. Sol supporting reviews
remain distinct from implementation. After the
coordinator independently runs `pnpm check` and the affected tests and inspects
their outputs, one final Astra on immutable `base..head` only if effective
`reviewer` is pinned available Astra and zero `reviewer-*` leaves; else ask
@ultimate for a configuration decision. Same reviewer for corrections. Copy
reviewed briefs into the existing `plan`; do not add a second ledger.

On go, existing build authority still applies if scope is unchanged. No extra
permission maze. Relay one Design review section to @ultimate; use the existing
question card only for real decisions.
